# Architecture: google-labs-code/stitch-skills

Research on the architecture of [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills) (Google Labs Stitch skills repo), read from primary sources on 2026-10-17. Every factual claim links the source file that owns it. Intended as a reference for maintaining skills in this repo (token-engine-builder), which builds colocated `src/skills/<skill>` packages into Vite-bundled `dist/<skill>` folders.

## 1. Repo layout: how skills are organized

Skills live under `plugins/`, grouped into three plugins. The grouping is [listed by the repo root](https://github.com/google-labs-code/stitch-skills) and the [README's repository-structure diagram](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): `stitch-design/` (core design workflows), `stitch-build/` (code generation and build), `stitch-utilities/` (design utilities and assistants). Each plugin is a directory `plugins/<plugin>/` holding a `plugin.json` manifest plus a `skills/` folder, per the [README structure diagram](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md).

The 15 skills, per the [README's Available Plugins tables](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md):

- `stitch-design/` (6): `code-to-design/`, `generate-design/`, `manage-design-system/`, `extract-design-md/`, `extract-static-html/`, `upload-to-stitch/`.
- `stitch-build/` (5): `react-components/`, `react-native/`, `react-vite-dashboard/`, `remotion/`, `shadcn-ui/`.
- `stitch-utilities/` (4): `design-md/`, `enhance-prompt/`, `stitch-loop/`, `taste-design/`.

A single skill is a directory named in kebab-case, for example [plugins/stitch-build/skills/react-components/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/react-components), containing:

- `SKILL.md` (required): frontmatter plus Markdown instructions.
- `scripts/` (most skills): executable helpers owned by the skill, for example `fetch-stitch.sh` and `validate.js` in [react-components/scripts/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/react-components/scripts), `snapshot.ts` / `extract_inline_html.ts` / `post_process.ts` in [extract-static-html/scripts/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/extract-static-html/scripts), and `verify-setup.sh` in [shadcn-ui/scripts/](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/shadcn-ui/scripts/verify-setup.sh).
- `resources/` **or** `references/` (naming varies by skill): agent-consumed knowledge, for example `architecture-checklist.md`, `component-template.tsx`, `stitch-api-reference.md`, `style-guide.json` in [react-components/resources/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/react-components/resources), and per-framework extraction guides (`react-tailwind.md`, `vue.md`, `svelte.md`, `angular.md`, `plain-css.md`) in [extract-design-md/references/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/extract-design-md/references).
- `examples/`: gold-standard references, for example `gold-standard-card.tsx` in [react-components/examples/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/react-components/examples), `DESIGN.md` in [extract-design-md/examples/](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/examples/DESIGN.md), and `auth-layout.tsx` / `data-table.tsx` / `form-pattern.tsx` in [shadcn-ui/examples/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/shadcn-ui/examples).
- `README.md` (build skills): a short per-skill page with install command, example prompt, and pipeline summary, for example the [react-components README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/README.md).
- `package.json` + `package-lock.json` (only skills with Node validator dependencies): [react-components/package.json](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/package.json) and the [react-native equivalent](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-native/package.json), both declaring `@swc/core` for validation.

The canonical per-skill shape is stated in the [README's Repository Structure section](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): `SKILL.md` ("Mission Control"), `scripts/` ("Validation & Networking"), `resources/` ("Checklists & Style Guides"), `examples/` ("Gold Standard" references). The [react-components README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/README.md) repeats the same shape with `package.json` added. Not every skill fills every slot: [upload-to-stitch/](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/upload-to-stitch) is minimal (`SKILL.md` + `scripts/` only), while `extract-design-md` uses `references/` instead of `resources/`.

Repo-level scaffolding around the skills (from the [root listing](https://github.com/google-labs-code/stitch-skills)):

- [README.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): user-facing index with quick start, prerequisites (Stitch MCP server), per-plugin skill tables with prompt examples, repository-structure diagram, and new-skill guidance.
- `plugins/<plugin>/plugin.json`: plugin manifests, for example [stitch-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/plugin.json), [stitch-build](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/plugin.json), [stitch-utilities](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/plugin.json) (see section 4).
- `plugins/<plugin>/.codex-plugin/plugin.json`: Codex UI metadata sidecar, for example [stitch-build's](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/.codex-plugin/plugin.json) (see section 4).
- [.agents/plugins/marketplace.json](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.agents/plugins/marketplace.json): marketplace manifest registering the three plugins (see section 4).
- [.github/workflows/validate-skills.yml](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.github/workflows/validate-skills.yml): the only CI workflow (see section 5).
- [CONTRIBUTING.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/CONTRIBUTING.md): fork/branch/PR process plus Google CLA and community guidelines; no skill-authoring rules live here (those live in the README).
- [LICENSE](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/LICENSE) (Apache-2.0), [SECURITY.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/SECURITY.md) (vulnerability reporting), `.gitignore`.

Cross-skill dependencies are expressed as named delegation instructions in the body: [code-to-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/code-to-design/SKILL.md) orchestrates three other skills in sequence (`extract-static-html` → `extract-design-md` → `upload-to-stitch`) and links the next skill's file (`[skills/extract-static-html/SKILL.md](../extract-static-html/SKILL.md)`); [generate-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md) delegates design-system work to the **manage-design-system** skill and image upload to the **upload-to-stitch** skill; [manage-design-system](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/SKILL.md) delegates DESIGN.md synthesis to the `design-md` skill in the `stitch-utilities` plugin. The README [warns](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) that selectively installed skills must include all required dependencies.

## 2. SKILL.md anatomy: frontmatter fields and semantics

The format follows the [Agent Skills specification](https://agentskills.io/specification): a skill directory contains at minimum `SKILL.md`, which holds YAML frontmatter followed by Markdown instructions, with optional `scripts/`, `references/`, and `assets/` conventions. Agents load skills progressively: frontmatter metadata at startup (~100 tokens), full body on activation (<5000 tokens recommended, `SKILL.md` under 500 lines), resources on demand.

Required frontmatter fields per the [specification](https://agentskills.io/specification):

- `name`: 1-64 characters; lowercase letters, numbers, and hyphens only; must not start/end with a hyphen or contain consecutive hyphens; **must match the parent directory name**.
- `description`: 1-1024 characters, non-empty; describes what the skill does **and when to use it**, with keywords that help agents match tasks. The [generate-design frontmatter](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md) shows the folded-block-scalar trigger style, and [extract-design-md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/SKILL.md) packs long trigger phrasing (`"Use this skill whenever…"`, `"even if they just say…"`) into the description.

Observed `name` values split into two families:

- `stitch::`-prefixed: [stitch::generate-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md), [stitch::react-components](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md), [stitch::react-native](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-native/SKILL.md), [stitch::code-to-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/code-to-design/SKILL.md), [stitch::manage-design-system](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/SKILL.md), [stitch::extract-design-md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/SKILL.md), [stitch::extract-static-html](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-static-html/SKILL.md), [stitch::upload-to-stitch](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/upload-to-stitch/SKILL.md).
- Plain kebab-case: [remotion](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/remotion/SKILL.md), [shadcn-ui](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/shadcn-ui/SKILL.md), [react-vite-dashboard](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-vite-dashboard/SKILL.md), [design-md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/design-md/SKILL.md), [enhance-prompt](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/enhance-prompt/SKILL.md), [stitch-loop](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/stitch-loop/SKILL.md), [taste-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/taste-design/SKILL.md).

Two verifiable spec deviations follow from the `stitch::` family: the [specification](https://agentskills.io/specification) allows only lowercase alphanumerics and hyphens in `name` (colons excluded) and requires `name` to match the parent directory name (directories are plain kebab-case, e.g. `generate-design/`). The repo itself acknowledges the cost: the [README's OpenCode section](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) states OpenCode requires `name` to be lowercase kebab-case matching the directory, so `stitch::…` skills need the `name` field and folder renamed before OpenCode will load them.

Optional spec fields (`license`, `compatibility`, `metadata`) are documented in the [specification](https://agentskills.io/specification) but none of the sampled SKILL.md files use them.

Repo-wide frontmatter extension (no spec equivalent beyond the experimental field):

- `allowed-tools` on every sampled skill, written as a YAML **list** (the [specification](https://agentskills.io/specification) describes it as a space-separated **string** and marks it experimental). The dominant pattern is MCP wildcard plus harness tools: [generate-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md) lists `"stitch*:*"`, `"Bash"`, `"Read"`, `"Write"`, `"web_fetch"`, repeated across the design/build skills. Variants: [taste-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/taste-design/SKILL.md) uses `"StitchMCP"` instead of the wildcard; [remotion](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/remotion/SKILL.md) adds `"remotion*:*"`; [shadcn-ui](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/shadcn-ui/SKILL.md) uses `"shadcn*:*"` and `"mcp_shadcn*"` with no `stitch*` entry; [enhance-prompt](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/enhance-prompt/SKILL.md) lists only `"Read"` and `"Write"`; [stitch-loop](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/stitch-loop/SKILL.md) adds `"chrome*:*"`.

The Markdown body after the frontmatter has no format restrictions per the [specification](https://agentskills.io/specification). In this repo it holds long procedural workflows with two recurring control devices:

- **GATEs**: [react-components](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md) declares every phase `MANDATORY` with completion gates (Phase 1 complete only when all screens are downloaded via script _and_ visually audited; Phase 2 complete only when `style-guide.json` is re-extracted from the current project; every component must satisfy all architectural rules) plus anti-pattern lists per phase.
- **User-confirmation checkpoints**: [extract-static-html](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-static-html/SKILL.md) must ask the user to choose a strategy (recommending Puppeteer) and to confirm the running app before snapshotting; [manage-design-system](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/SKILL.md) must present the design-system summary and wait for explicit approval before uploading; [upload-to-stitch](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/upload-to-stitch/SKILL.md) must present file paths/sizes/types and wait for approval before running the upload script; [react-components](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md) Phase 4 requires asking permission before validation scripts, dev servers, or browser testing.

File references stay one level deep from the skill root per the [specification](https://agentskills.io/specification): [generate-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md) links `references/design-mappings.md`, `references/prompt-keywords.md`, and `examples/enhanced-prompt.md`; [extract-design-md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/SKILL.md) requires the YAML-frontmatter format of [examples/DESIGN.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/examples/DESIGN.md); [manage-design-system](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/SKILL.md) links `reference/tool-schema.md` and `examples/metadata.json`.

## 3. Executable layer: how scripts ship and run

Scripts ship as source beside the skill and are executed by the agent at use time (via `Bash`/`run_command`); there is no bundling, no compile step, and no dependency inlining. Runtime prerequisites live outside the repo (Stitch MCP server, plus per-skill extras) and are installed or connected at use time.

Concretely, per skill:

- `react-components` / `react-native`: `scripts/fetch-stitch.sh` (a [curl wrapper](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/scripts/fetch-stitch.sh) — `curl -L -f -sS --connect-timeout 10 --compressed` — for high-reliability download of signed Google Cloud Storage URLs that agent fetch tools mishandle) and `scripts/validate.js` (a [Node AST validator](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/scripts/validate.js) on `@swc/core` that parses TSX, requires a `*Props` interface, and fails on hardcoded hex values in `className`; exits 0/1). Dependencies come from the skill's own [package.json](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/package.json) (`@swc/core`, `node >= 18`, `validate`/`fetch` npm scripts) installed at use time: the [SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md) runs `npm install` if `node_modules` is missing, and CI runs [npm ci](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.github/workflows/validate-skills.yml).
- `shadcn-ui`: `scripts/verify-setup.sh`, an [advisory checker](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/shadcn-ui/scripts/verify-setup.sh) (bash, `set -e`) that verifies `components.json`, Tailwind config, `tsconfig.json` path aliases, global CSS with Tailwind directives and CSS variables, `components/ui/`, `lib/utils.ts` with `cn()`, and required/recommended dependencies — printing fix suggestions (`npx shadcn@latest init`) rather than failing closed.
- `remotion`: `scripts/download-stitch-asset.sh`, a [curl downloader](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/remotion/scripts/download-stitch-asset.sh) (`curl -L -f`, removes the output file on failure) for screen assets.
- `extract-static-html`: `scripts/snapshot.ts` (a [Puppeteer-based snapshot tool](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-static-html/scripts/snapshot.ts), run via `npx tsx`, with `--url`/`--output`/`--wait`/`--viewport`/`--html-class`/`--remove-fixed`/`--full-height`/`--title`/`--timeout`/`--concurrency`/`--json` flags) that captures the rendered DOM with inlined CSS and base64 images, plus `extract_inline_html.ts` and `post_process.ts` in the [same directory](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/extract-static-html/scripts).
- `upload-to-stitch`: `scripts/upload_to_stitch.py` in the skill's [scripts/ directory](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/upload-to-stitch), invoked per the [tool-schema reference](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/reference/tool-schema.md) as `python3 <SKILL_DIR>/scripts/upload_to_stitch.py --project-id … --file-path … --api-key …`. It exists because, per the [upload-to-stitch SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/upload-to-stitch/SKILL.md), base64-encoding even a small file exceeds the model's ~16K output token limit, so the script reads the file and POSTs it to `/v1/projects/{projectId}/screens:batchCreate` over HTTP. The API key is extracted from local MCP config files (Antigravity, Gemini CLI, Claude Code paths listed in the SKILL.md) or requested from the user.

Agent-consumed resources (never executed, read on demand):

- `resources/style-guide.json`: a [per-project token file](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/resources/style-guide.json) (colors, typography, spacing) that Phase 2 of the [react-components workflow](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md) overwrites from the current project's HTML `<head>` `tailwind.config` — reusing another project's tokens is an explicit anti-pattern.
- `resources/architecture-checklist.md`: a [quality gate](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/resources/architecture-checklist.md) (hooks extraction, no monoliths, `mockData.ts` decoupling, `Readonly` Props, valid TS, `dark:` variants, no hardcoded hex).
- `resources/component-template.tsx`: a [scaffolding template](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/resources/component-template.tsx) with a `StitchComponent` placeholder name the agent must replace.
- `resources/stitch-api-reference.md`: [MCP data-shape documentation](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/resources/stitch-api-reference.md) (`get_screen` download URLs, `data-stitch-id` preservation, asset/token extraction rules).
- `references/` guides in `extract-design-md` ([framework-specific extraction patterns](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-design/skills/extract-design-md/references)) and `reference/tool-schema.md` in `manage-design-system` ([MCP call schemas](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/reference/tool-schema.md)).

`examples/` hold gold-standard, syntactically valid references: the [`gold-standard-card.tsx`](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/react-components/examples) validated in CI (see section 5), the [DESIGN.md example](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/examples/DESIGN.md) whose YAML frontmatter (`name`, `colors`, `typography`, `rounded`, `spacing`) is mandatory for downstream parsing, and the shadcn [component examples](https://github.com/google-labs-code/stitch-skills/tree/main/plugins/stitch-build/skills/shadcn-ui/examples).

External runtime surface assumed by the skills: the [Stitch MCP server](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) (required everywhere; skills start with `list_tools` namespace discovery), plus Remotion MCP/CLI ([remotion](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/remotion/SKILL.md)), shadcn MCP ([shadcn-ui](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/shadcn-ui/SKILL.md)), Chrome DevTools MCP ([stitch-loop](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/stitch-loop/SKILL.md)), and `puppeteer` for the snapshot script ([extract-static-html](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-static-html/SKILL.md)).

## 4. Distribution and install model

Two routes, stated in the [README Quick Start](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): install plugins (recommended, full suite) or install skills selectively. The README's [help note](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) points at `npx plugins --help` and `npx skills --help` for the installer CLIs.

Plugin route (managed, per harness):

- Codex CLI: register the marketplace then install any combination of `stitch-design`, `stitch-build`, `stitch-utilities`, per the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): `codex plugin marketplace add google-labs-code/stitch-skills --ref main --sparse .agents/plugins --sparse plugins/stitch-design --sparse plugins/stitch-build --sparse plugins/stitch-utilities` (`--sparse` optional, limits the checkout to those paths). Codex UI alternative with Source/Git-ref/Sparse-paths form fields is also documented in the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md).
- Claude Code: `npx plugins add google-labs-code/stitch-skills --scope project --target claude-code` (installs into the current project), per the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md).
- Cursor: `npx plugins add google-labs-code/stitch-skills --scope workspace --target cursor` (installs into the current workspace), per the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md).
- OpenCode (manual; no marketplace support): copy skill folders into `.opencode/skills/` (also discovers `.claude/skills/`, `.agents/skills/`), rename non-kebab `stitch::…` names, ignore extra frontmatter like `allowed-tools`, adapt MCP tool names (`webfetch`/`bash`), and add the Stitch MCP remote entry manually — all per the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md).

Selective route: `npx skills add google-labs-code/stitch-skills`, per the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md), with a per-skill form shown in the [react-components README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/README.md): `npx skills add google-labs-code/stitch-skills --skill react:components --global`. The README carries an [inter-dependency warning](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md): selective installs must include all required dependencies.

The manifests behind the plugin route:

- [.agents/plugins/marketplace.json](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.agents/plugins/marketplace.json): marketplace `stitch-skills` registering the three plugins as `local` sources at `./plugins/<name>`, each `installation: AVAILABLE`, `authentication: ON_INSTALL`, `category: Productivity`.
- `plugins/<plugin>/plugin.json`: name, description, `version: 1.0.0`, author, homepage/repository, `license: Apache-2.0`, keywords — see [stitch-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/plugin.json), [stitch-build](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/plugin.json), [stitch-utilities](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/plugin.json).
- `plugins/<plugin>/.codex-plugin/plugin.json`: Codex UI metadata with `"skills": "./skills/"` plus an `interface` block (`displayName`, `shortDescription`, `longDescription`, `category`, `capabilities`, `defaultPrompt`, `brandColor`), for example [stitch-build's](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/.codex-plugin/plugin.json).

No version pin or ref is documented for the `npx` routes (they track the repo); the Codex route pins `--ref main`. After install, the [prerequisites](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) apply: the Stitch MCP server must be configured per the Stitch MCP setup guide before any skill runs.

## 5. Versioning and evolution

One static version per plugin, no release machinery:

- Each `plugin.json` carries `"version": "1.0.0"` ([stitch-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/plugin.json), [stitch-build](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/plugin.json), [stitch-utilities](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/plugin.json)); the two skill-level `package.json` files are also `1.0.0` ([react-components](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/package.json), [react-native](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-native/package.json)).
- The [SECURITY.md supported-versions table](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/SECURITY.md) lists `0.1.x` as supported — a different version line from the `1.0.0` plugin manifests.
- No CHANGELOG, no changesets, and no release workflow were observed at the [repo root](https://github.com/google-labs-code/stitch-skills). The only automation is [.github/workflows/validate-skills.yml](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.github/workflows/validate-skills.yml), which runs on push/PR to `main` and executes `node scripts/validate.js examples/gold-standard-card.tsx` (after `npm ci` on Node 18) for exactly two skills: `react-components` and `react-native`.
- Individual skills carry no version: the spec's optional `metadata.version` field (per the [specification](https://agentskills.io/specification)) is not used on any sampled skill.
- Consumers update by re-installing the marketplace plugin or re-running the `npx skills add` command; no update command is documented in-repo.
- Support status is explicit: the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) and [SECURITY.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/SECURITY.md) both state this is not an officially supported Google product and is ineligible for the Google Open Source Software Vulnerability Rewards Program.

## 6. Comparison with token-engine-builder (neutral observations)

References to this repo are local paths relative to the token-engine-builder root: [ARCHITECTURE.md](../../ARCHITECTURE.md), [README.md](../../README.md), [package.json](../../package.json).

Where the two architectures already match:

- Colocated per-skill source packages: `src/skills/<skill>/` holding `SKILL.md` plus skill-owned files mirrors the upstream one-directory-per-skill layout (`SKILL.md` plus owned `scripts/`/`resources/`/`examples/`). Both repos keep `SKILL.md` at the package root.
- Trigger-style `description` frontmatter stating what the skill does and when to use it, matching the shape defined by the [specification](https://agentskills.io/specification).
- Copy-to-install distribution: a built `dist/<skill>/` folder copied to `~/agents/skills/<skill-name>/` (see [README.md](../../README.md)) parallels the upstream copy-folder model for OpenCode (see the [README](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md)).
- Skill-owned resources travel with the skill: local `templates/` and `assets/` mirrored into `dist/` (see [ARCHITECTURE.md](../../ARCHITECTURE.md)) parallel the upstream convention of sibling `resources/`/`references/`/`examples/` directories (per the [README structure diagram](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/README.md) and the [specification](https://agentskills.io/specification)).
- Token-consistency enforcement inside the skill: upstream's `validate.js` hex-gate plus the per-project `style-guide.json` re-extraction gate (per the [react-components SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md)) parallel the local `token-audit` WCAG gate and the alias-only discipline above Tier 1 (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).
- `DESIGN.md` as a machine-readable token contract: the [DESIGN.md example frontmatter](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-design-md/examples/DESIGN.md) (`name`, `colors`, `typography`, `rounded`, `spacing`) parallels the local `style-spec.json` anchor contract and 3-tier token tree (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).

Where the two architectures diverge:

- Source-distributed versus bundled: upstream ships skill scripts as source with dependencies installed at use time (`npm install`/`npm ci` per the [react-components SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-components/SKILL.md) and [validate-skills.yml](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.github/workflows/validate-skills.yml); `puppeteer` via `npx tsx` per [snapshot.ts](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/extract-static-html/scripts/snapshot.ts)); token-engine-builder compiles each skill's `scripts/*.ts` into self-contained `.mjs` with dependencies inlined via per-skill Vite SSR/Node passes so installed folders run with no install (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).
- MCP-tool-first versus CLI-first executables: upstream skills center on Stitch MCP calls (namespace discovery, `get_screen`, `generate_screen_from_text`) with scripts as networking/validation helpers; local skills center on runnable CLIs (`node scripts/<name>.mjs`, no install, per [README.md](../../README.md)).
- Plugin grouping versus flat skills: upstream sorts 15 skills into 3 versioned plugins with marketplace and Codex manifests (per [.agents/plugins/marketplace.json](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.agents/plugins/marketplace.json) and [stitch-build's codex manifest](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/.codex-plugin/plugin.json)); local `src/skills/` is flat with four pipeline skills and no manifest layer.
- `allowed-tools` frontmatter versus none locally: every sampled upstream skill declares tool permissions including MCP wildcards (for example [generate-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/generate-design/SKILL.md)); local skills carry no such field (the local `token-build` SKILL.md instead uses the spec's `license` and `compatibility` fields, which upstream skills do not use).
- Namespaced versus directory-matching names: upstream `stitch::` names diverge from the spec's charset and directory-match rules (see section 2); local skill names are plain kebab-case matching their directories.
- Run-time skill orchestration versus file-pipeline orchestration: upstream chains skills by delegation at run time (`code-to-design` sequencing three skills, per its [SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/code-to-design/SKILL.md)); the local pipeline passes artifacts through files (`style-spec.json` → `tokens/` → gate → CSS, per [README.md](../../README.md)).
- Token direction reversed: upstream extracts/describes/applies tokens so a hosted design AI generates screens (DESIGN.md → `create_design_system_from_design_md` → `apply_design_system`, per the [manage-design-system SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-design/skills/manage-design-system/SKILL.md)); token-engine-builder derives tokens from a math anchor into static CSS consumables (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).
- Token vocabulary depth: upstream DESIGN.md output uses descriptive natural language plus hex (for example [design-md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/design-md/SKILL.md) and [taste-design](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/taste-design/SKILL.md) with its banned-patterns list: no purple/blue neon, no `Inter`, no pure black, max one accent); local tokens are DTCG-typed OKLCH values with measured contrast (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).
- `react-vite-dashboard` consumes DESIGN.md tokens for data-dense dashboards with TanStack Query and Web3 read patterns (per its [SKILL.md](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-build/skills/react-vite-dashboard/SKILL.md)); there is no upstream equivalent of emitting framework CSS (`tokens.css` + Tailwind v4 `@theme`) from tokens.
- No per-change versioning upstream: static `1.0.0` manifests plus a `0.1.x` security table and no changelog/changesets (see section 5); the local [package.json](../../package.json) is `private: true` at `0.1.0` and carries `@changesets/cli` with `changeset`/`release` scripts.
- Validation scope: upstream CI checks only syntactic/AST validity of two gold-standard examples (per [validate-skills.yml](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/.github/workflows/validate-skills.yml)); there is no measured-gate equivalent to the local audit smoke run (see [ARCHITECTURE.md](../../ARCHITECTURE.md)).
